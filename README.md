# Road Damage Analysis

Android / iOS のブラウザで、動画と GPS を同時に記録する PWA です。HTTPS で配信してください（開発時は localhost でも動作します）。

## 使い方

1. カメラとGPSのアイコンが並んだボタンを押し、ブラウザの権限を許可します。それぞれ利用可能になるとアイコンにチェックが付きます。読み上げラベルでも状態を確認できます。
2. 新しい GPS 位置情報が得られたら中央の録画ボタンで撮影を開始・停止します。音声が必要な場合は「音声も録音する」を選択します。
3. 停止した録画は「Recorded Data / 録画データ」に保存されます。プルダウンで動画を選択・変更すると「Playback / データの再生」に動画と軌跡を自動表示します。再生・シークに合わせて位置が中央に表示されます。
4. 過去の記録は「過去の動画・位置情報を読み込む」で保存フォルダーを開き、動画を選択します。同じフォルダーの位置情報をファイル名で自動選択します。位置情報の選択欄はありません。GPS ファイルがなくても動画を再生できます。
5. 選択した動画・GPSログ・フレーム対応表は「Repository / データの保存」からダウンロードできます。ファイル名の共通 ID で組み合わせを判別できます。

画面上部のナビゲーションで撮影・録画データ・再生・保存へ移動できます。再生画面には5秒送り／戻し、0.5〜2倍速の切り替えがあります。通常時の地図説明は表示せず、タイル取得失敗など対応が必要な場合だけ案内します。

## 動画の読み込みと位置情報の自動照合

ブラウザは動画1ファイルの選択だけでは隣のファイルにアクセスできないため、最初に動画と位置情報を含むフォルダーへの読み取りを許可してください。以降は動画のプルダウンを選ぶだけで対応する位置情報を照合します。動画が1本の場合は自動選択します。フォルダーの選択はこの画面を開いている間保持します。

フォルダーを選択できない端末・ファイル提供元では「ファイルを開く」で動画と関連ファイルをまとめて選択できます。この場合も位置情報専用の選択操作は不要です。同じ端末に録画が残っている場合、書き出した動画だけを開いても、ファイル名の記録IDとサイズが一致すれば端末内の位置情報を再利用します。

照合対象は動画と同じフォルダーの共通名です。例えば `road_damage_ID.webm` に対して `road_damage_ID_metadata.json`、`road_damage_ID_metadata.json.txt`、`road_damage_ID_gps.csv` を照合し、JSONを優先します。旧版の `recording_ID` / `metadata_ID` / `gps_ID` 形式、動画と同じベース名のJSON・CSVにも対応します。展開済みZIPの `video.webm` / `metadata.json` / `gps.csv` は同じフォルダーに動画が1本の場合に対応します。別フォルダーや部分一致のログは使いません。重複して区別できない場合は読み込みを止め、対応ログがない場合は動画のみ読み込みます。旧版の frames 配列、BOM 付きCSVにも対応します。

## 録画の画質

録画前に「録画の画質」を選択します。設定は次回起動時も保持します。標準の目標ビットレートを従来の6 Mbpsから16 Mbpsに引き上げ、道路の細部が圧縮で失われにくくなるようにしました。プレビューは映像を切り取らず全体を表示します。

| 設定 | 希望する解像度・fps | 目標ビットレート |
| --- | --- | --- |
| 高画質（標準） | 1920 × 1080 / 30 fps | 16 Mbps |
| 最高画質 | 3840 × 2160 / 30 fps | 45 Mbps |
| 動き優先 | 1920 × 1080 / 60 fps | 24 Mbps |
| 容量優先 | 1280 × 720 / 30 fps | 6 Mbps |

解像度・fpsは端末に合わせて調整します。カメラ開始後に実際の入力解像度・fpsと概算容量を表示します。4Kや60fps、指定ビットレートの実現はカメラ・ブラウザ・エンコーダーによります。対応端末では連続オートフォーカス・露出・ホワイトバランスも設定します。録画中の画質変更は無効です。録画開始時の実際の入力設定と目標／エンコーダー報告ビットレートはmetadataの `capture` に記録します。高画質ほど容量が増え、既存の512 MB自動停止に早く到達します。

## 地図の操作

撮影中と再生中の地図は現在位置を中央に保ちます。地図下の＋／−ボタン、2本指のピンチ、マウスホイールで拡大・縮小できます。再生時刻と緯度経度・GPS精度は地図の外側に表示します。

Leaflet 1.9.4のCSS・JavaScript・画像を`vendor/leaflet/`に同梱しています。元のCSSに指定されていた誤った検証ハッシュを解消し、地図用CSSの読み込みが外部CDNの状態に左右されない構成です。地図タイルの取得失敗時は斜線背景と再取得ボタンを表示し、軌跡・位置マーカー・ズーム操作は維持します。地図サイズの再計算は表示サイズが変わった場合に限ります。

## ローカル・Dropboxへの保存

1. 「Repository / データの保存」でローカル（このデバイス）またはDropboxを選びます。
2. ローカルでは「保存」を押すだけでZIPの作成・保存まで行います。保存先ダイアログに対応するブラウザでは先に保存先を選び、その後ZIPを作成します。
3. Dropboxでは「アップロード」を押すと共有画面が開きます。Dropboxを選択して保存を完了してください。準備ボタンはありません。
4. Dropboxが共有先に出ない、複数ファイルをまとめて送れない場合は「個別にアップロード」を開き、「動画を共有」「GPSログを共有」「フレーム対応表を共有」をそれぞれ押します。Dropboxアプリのインストール・ログインが必要です。

共有用ファイルは録画終了・読み込み・動画選択時にWorkerで自動準備します。準備中はアップロードボタンを無効にして状態を表示し、完了後の1タップで共有できます。これによりAndroidで長い非同期準備の後に共有許可が失効する問題を避けます。データを選び直すと古い準備処理を破棄し、選択中の動画だけを共有します。

DropboxはOSの共有機能を使います。アプリ内OAuthログイン／自動アップロードではありません。ブラウザから共有先を強制選択したり、アップロード完了を確認したりはできません。共有キャンセル・転送失敗時は準備済みデータを保持して再試行できます。個別共有にも対応していない端末や大きな動画を転送できない場合は、ローカル保存してDropboxアプリからアップロードしてください。

AndroidではZIP/JSONのファイル共有を受け付けないブラウザがあるため、Dropboxに渡すのは動画（video/webmまたはvideo/mp4）、GPSログ（text/csv）、フレーム対応表（text/plain、ファイル名はmetadata.json.txt）です。ZIPの拡張子やMIMEだけを偽装して渡すことはありません。フレーム対応表の中身はJSONで、GPS実測値・推定フレーム位置を保持し、そのままアプリへ読み込めます。動画のMIMEからcodecsパラメーターを除き、共有時は不要なタイトルや本文を付けずファイルだけを渡します。

録画はまずブラウザの録画データに保存し、選択した保存先へは上記操作で書き出します。ローカルのZIPは動画を再圧縮せずまとめます。約4 GB以上は個別ダウンロードを利用してください。ZIPを取り込む場合は端末で展開して動画とJSONまたはCSVを選んでください。Dropboxの3ファイルは共通IDの付いたファイル名で組み合わせを判別できます。

## 保存と記録の仕様

- 動画と GPS は IndexedDB に保存します。一覧にはサマリーだけを読み込み、全動画をメモリに読み込むことはありません。
- 旧版は録画をメモリ内にだけ保持していました。既に失われた録画は復元できません。ダウンロード済みファイルを読み込んでください。
- ブラウザのデータ消去や端末の空き容量不足などで履歴を失う場合があります。重要な記録は端末のファイルにも保存してください。容量不足で保存できなかった場合は画面に表示し、その場でダウンロードできます。
- 録画中はアプリを前面に保ってください。非表示になると録画を終了して保存を試みます。OSによる強制終了時の保存は保証できません。利用できる端末では画面のスリープを抑止します。
- 1録画は512 MBを目安に自動停止します。MediaRecorderのデータ通知が遅延した場合はこれを超える場合があります。
- GPSはブラウザの測位サンプルです。各フレームの座標は補間による推定値であり、フレームごとに実測したGPSではありません。フレーム時刻もカメラの報告fpsに基づく推定値です。実際にエンコードされたフレーム時刻を保証しません。
- 動画形式は端末のMediaRecorder対応状況からWebMまたはMP4を選びます。他端末の動画を取り込む場合、使用中ブラウザがその動画形式に対応している必要があります。
- 地図はOpenStreetMap、地図ライブラリはLeafletを使用します。動画・GPSは共有操作まで端末内で処理します。地図タイルの取得先には表示範囲とIPアドレスが伝わります。
- PWA更新は録画を妨げないよう次回起動時に適用します。更新が見えない場合はこのアプリのタブとホーム画面のアプリを全て閉じて再度開いてください。

## 開発・検証

ビルド不要の静的アプリです。index.html / app.js / core.js / storage.js / map-view.js / export.js / export-worker.js / quality.js / import-controller.js / import-matching.js / sw.js / manifest.webmanifest / logo.png / tile-unavailable.svg と vendor/ ディレクトリを配信します。既存の録画を引き継ぐためIndexedDBの名前は変更していません。

`node --test tests/*.test.js`

テストは時刻補間、欠測、旧JSON/CSV、入力検証、並び順、推定fps、日付変更線、ZIPのCRC/構造、ファイル保存、Android相当の共有形式制限、個別共有、転送失敗・キャンセル、metadata.json.txtの再読み込みを検証します。

ブラウザ統合テスト（任意）: `npm install --no-save playwright`、`npx playwright install chromium`の後、`node tests/browser.mjs`。テスト映像・測位・地図タイル・共有先は模擬データ、Leaflet・MediaRecorder・IndexedDB・ZIP処理は実装を使います。`PLAYWRIGHT_MODULE`でPlaywrightのモジュールURL、`BROWSER_EXECUTABLE`でブラウザ実行ファイル、`TEST_OUTPUT_DIR`で検証画像とZIPの保存先を指定できます。

実機確認: Android Chrome / iOS Safari で、初回権限・拒否後の再許可、前後カメラ、音声、短時間録画、再起動後の履歴、再生とシーク、ピンチ操作、旧ファイル読み込み、バックグラウンド移行、保存容量不足、各クラウドアプリへの共有を確認してください。
